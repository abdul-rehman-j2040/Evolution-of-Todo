## Todo Entity

### Dataclass Definition

```python
from dataclasses import dataclass
from datetime import datetime
from .enums import Priority, Status

@dataclass
class Todo:
    """
    Represents a single task/todo item.

    Attributes:
        id: Unique sequential identifier (starts at 1)
        title: Task title (1-200 characters)
        description: Optional task description (0-1000 characters)
        priority: Priority level (High, Medium, Low)
        status: Task status (Pending, Completed)
        created_at: UTC timestamp of task creation
    """
    id: int
    title: str
    description: str
    priority: Priority
    status: Status
    created_at: datetime
```

### Field Specifications

| Field | Type | Required | Default | Constraints | Auto-Generated | Notes |
|-------|------|----------|---------|-------------|----------------|-------|
| `id` | `int` | Yes | Auto | Unique, sequential, >0 | Yes | Assigned by TodoService |
| `title` | `str` | Yes | - | 1-200 characters | No | Trimmed automatically |
| `description` | `str` | No | `""` | 0-1000 characters | No | Optional field |
| `priority` | `Priority` | Yes | `MEDIUM` | Valid enum value | No | Default if not specified |
| `status` | `Status` | Yes | `PENDING` | Valid enum value | Yes | Always Pending on creation |
| `created_at` | `datetime` | Yes | Auto | Valid datetime | Yes | UTC timestamp |

### Field Details

#### `id` (int)
- **Purpose**: Unique identifier for each task
- **Generation**: Assigned sequentially by TodoService starting at 1
- **Uniqueness**: Guaranteed unique within a service instance session
- **Immutable**: Never changes after creation
- **Validation**: Must be positive integer (>0)
- **Phase II**: Will be auto-generated by database (PostgreSQL SERIAL or AUTO_INCREMENT)

#### `title` (str)
- **Purpose**: Brief description of the task
- **Required**: Yes (cannot be empty after trimming)
- **Length**: 1-200 characters
- **Trimming**: Leading/trailing whitespace automatically removed
- **Empty Check**: Validated after trimming (empty string rejected)
- **Examples**:
  - Valid: `"Buy groceries"`, `"Fix login bug"`
  - Invalid: `""`, `"   "` (empty after trim)
  - Invalid: `"A" * 201` (exceeds 200 characters)

#### `description` (str)
- **Purpose**: Detailed explanation or notes about the task
- **Required**: No (defaults to empty string)
- **Length**: 0-1000 characters
- **Trimming**: Leading/trailing whitespace preserved (user intent)
- **Empty String**: Valid (treated as "no description")
- **Examples**:
  - Valid: `""`, `"Milk, eggs, bread"`, `"Details about the bug..."`
  - Invalid: `"A" * 1001` (exceeds 1000 characters)

#### `priority` (Priority)
- **Purpose**: Indicates task urgency/importance
- **Required**: Yes (defaults to MEDIUM if not specified)
- **Enum**: Priority.HIGH, Priority.MEDIUM, Priority.LOW
- **Default**: `Priority.MEDIUM`
- **Validation**: Must be valid Priority enum member
- **Case Handling**: CLI accepts case-insensitive input (converted to enum)

#### `status` (Status)
- **Purpose**: Indicates task completion state
- **Required**: Yes (always PENDING on creation)
- **Enum**: Status.PENDING, Status.COMPLETED
- **Default**: `Status.PENDING` (automatically assigned)
- **Immutable on Creation**: Always starts as PENDING
- **Update**: Changed via `TodoService.complete_task()` method
- **Future**: May add Status.ARCHIVED, Status.CANCELED in Phase V

#### `created_at` (datetime)
- **Purpose**: Timestamp of task creation for sorting/display
- **Required**: Yes (automatically assigned)
- **Timezone**: UTC (datetime.utcnow())
- **Immutable**: Never changes after creation
- **Format**: ISO 8601 for display (YYYY-MM-DD HH:MM:SS)
- **Future**: May add `updated_at` field in Phase V

## Enumerations

### Priority Enum

```python
from enum import Enum

class Priority(str, Enum):
    """
    Task priority levels.

    Inherits from str to enable string comparison and JSON serialization.
    """
    HIGH = "High"
    MEDIUM = "Medium"
    LOW = "Low"
```

**Values**:
- `Priority.HIGH` → `"High"`
- `Priority.MEDIUM` → `"Medium"`
- `Priority.LOW` → `"Low"`

**Default**: `Priority.MEDIUM`

**String Inheritance**: Enum inherits from `str` to enable:
- JSON serialization without custom encoder
- String comparison: `priority == "High"`
- Database storage as VARCHAR
- Phase II FastAPI automatic validation

**CLI Parsing** (case-insensitive):
```python
def parse_priority(value: str) -> Priority:
    """Convert user input to Priority enum (case-insensitive)"""
    mapping = {
        "high": Priority.HIGH,
        "h": Priority.HIGH,
        "medium": Priority.MEDIUM,
        "m": Priority.MEDIUM,
        "med": Priority.MEDIUM,
        "low": Priority.LOW,
        "l": Priority.LOW,
    }
    normalized = value.strip().lower()
    if normalized not in mapping:
        raise ValueError(f"Invalid priority: {value}. Use high, medium, or low.")
    return mapping[normalized]
```

**Usage Examples**:
```python
# Creation with default
todo = Todo(id=1, title="Task", priority=Priority.MEDIUM, ...)

# CLI: todo add "Task" -p high
priority = parse_priority("high")  # → Priority.HIGH

# Comparison
if todo.priority == Priority.HIGH:
    print("Urgent!")
```

### Status Enum

```python
from enum import Enum

class Status(str, Enum):
    """
    Task completion status.

    Inherits from str for JSON serialization and database compatibility.
    """
    PENDING = "Pending"
    COMPLETED = "Completed"
```

**Values**:
- `Status.PENDING` → `"Pending"`
- `Status.COMPLETED` → `"Completed"`

**Default**: `Status.PENDING` (all new tasks)

**String Inheritance**: Same benefits as Priority enum

**CLI Parsing** (case-insensitive):
```python
def parse_status(value: str) -> Status:
    """Convert user input to Status enum (case-insensitive)"""
    mapping = {
        "pending": Status.PENDING,
        "p": Status.PENDING,
        "completed": Status.COMPLETED,
        "complete": Status.COMPLETED,
        "c": Status.COMPLETED,
        "done": Status.COMPLETED,
    }
    normalized = value.strip().lower()
    if normalized not in mapping:
        raise ValueError(f"Invalid status: {value}. Use pending or completed.")
    return mapping[normalized]
```

**Usage Examples**:
```python
# All tasks start as pending
todo = Todo(id=1, title="Task", status=Status.PENDING, ...)

# Marking complete
todo.status = Status.COMPLETED

# CLI list filtering: todo list --status pending
filtered = [t for t in tasks if t.status == Status.PENDING]
```

**Future Extensions** (Phase V):
- `Status.ARCHIVED` - Completed tasks moved to archive
- `Status.CANCELED` - Tasks abandoned without completion
- `Status.IN_PROGRESS` - Tasks actively being worked on

## Validation Rules

### Title Validation

**Rules**:
1. Required (cannot be None or empty after trimming)
2. Minimum length: 1 character (after trimming)
3. Maximum length: 200 characters
4. Leading/trailing whitespace: Automatically trimmed
5. Empty after trimming: Rejected with error

**Implementation**:
```python
def validate_title(title: str) -> tuple[Optional[str], Optional[str]]:
    """
    Validate task title.

    Returns: (normalized_title, error_message)
    """
    if not title:
        return None, "Title cannot be empty"

    normalized = title.strip()

    if not normalized:
        return None, "Title cannot be empty"

    if len(normalized) > 200:
        return None, "Title cannot exceed 200 characters"

    return normalized, None
```

**Test Cases**:
```python
# Valid
validate_title("Buy groceries")           # → ("Buy groceries", None)
validate_title("  Fix bug  ")             # → ("Fix bug", None)
validate_title("A" * 200)                 # → ("AAA...", None)

# Invalid
validate_title("")                        # → (None, "Title cannot be empty")
validate_title("   ")                     # → (None, "Title cannot be empty")
validate_title("A" * 201)                 # → (None, "Title cannot exceed 200 characters")
```

### Description Validation

**Rules**:
1. Optional (can be empty string)
2. Minimum length: 0 characters
3. Maximum length: 1000 characters
4. Leading/trailing whitespace: Preserved (user intent)
5. Empty string: Valid (no description)

**Implementation**:
```python
def validate_description(description: str) -> tuple[Optional[str], Optional[str]]:
    """
    Validate task description.

    Returns: (description, error_message)
    """
    if len(description) > 1000:
        return None, "Description cannot exceed 1000 characters"

    return description, None
```

**Test Cases**:
```python

validate_description("")                  # → ("", None)
validate_description("Milk, eggs, bread") # → ("Milk, eggs, bread", None)
validate_description("  Indented  ")      # → ("  Indented  ", None)  # Preserves whitespace
validate_description("A" * 1000)          # → ("AAA...", None)

# Invalid
validate_description("A" * 1001)          # → (None, "Description cannot exceed 1000 characters")
```

### Priority Validation

**Rules**:
1. Must be valid Priority enum member
2. Case-insensitive CLI input
3. Shorthand accepted (h/m/l)
4. Invalid value: Rejected with error

**Implementation**: See Priority enum section above

**Test Cases**:
```python

parse_priority("h")       # → Priority.HIGH
```

### ID Validation

**Rules**:
1. Must be positive integer (>0)
2. Non-existent ID: Returns None or error tuple
3. Negative ID: Rejected with error
4. Zero: Rejected with error

**Implementation**:
```python
def validate_id(id_str: str) -> tuple[Optional[int], Optional[str]]:
    """
    Validate task ID from CLI input.

    Returns: (task_id, error_message)
    """
    try:
        task_id = int(id_str)
    except ValueError:
        return None, "Invalid task ID. Must be a positive integer"

    if task_id <= 0:
        return None, "Invalid task ID. Must be a positive integer"

    return task_id, None
```

**Test Cases**:
```python

validate_id("42")     # → (42, None)
validate_id("999")    # → (999, None)

# Invalid

validate_id("-1")     # → (None, "Invalid task ID. Must be a positive integer")
validate_id("abc")    # → (None, "Invalid task ID. Must be a positive integer")
validate_id("")       # → (None, "Invalid task ID. Must be a positive integer")
```

## Phase II Migration

### Dataclass → SQLModel

```python
# Phase I: Dataclass
@dataclass
class Todo:
    id: int
    title: str
    description: str
    priority: Priority
    status: Status
    created_at: datetime

# Phase II: SQLModel (extends Pydantic + SQLAlchemy)
from sqlmodel import Field, SQLModel

class Todo(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    title: str = Field(max_length=200, index=True)
    description: str = Field(default="", max_length=1000)
    priority: Priority = Field(default=Priority.MEDIUM)
    status: Status = Field(default=Status.PENDING, index=True)
    created_at: datetime = Field(default_factory=datetime.utcnow, index=True)
    user_id: int = Field(foreign_key="user.id")  # Multi-user support

    # Relationships (SQLAlchemy)
    user: Optional["User"] = Relationship(back_populates="todos")
```

**Key Changes**:
- `id` becomes Optional (auto-generated by database)
- Field constraints added (max_length, index, foreign_key)
- `user_id` added for multi-user data isolation
- SQLAlchemy relationships added

**Service Compatibility**: TodoService methods remain unchanged (same signatures)
